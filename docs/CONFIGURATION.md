# Конфигурация OPDS Desk

OPDS Desk хранит пользовательскую конфигурацию и рабочее состояние локально на компьютере пользователя. Этот документ описывает расположение данных, параметры конфигурации, сохранённое состояние очереди и практические меры для резервного копирования и сброса.

## Каталог данных приложения

Для новой установки основной каталог данных приложения строится из переменной окружения `LOCALAPPDATA`:

```text
%LOCALAPPDATA%\OPDSDesk
```

Например:

```text
C:\Users\<User>\AppData\Local\OPDSDesk
```

Текущий код вычисляет `APP_DATA_BASE_DIR` как значение `LOCALAPPDATA`. Если эта переменная отсутствует, используется `os.path.expanduser("~")`. Затем основной каталог OPDS Desk вычисляется как `<APP_DATA_BASE_DIR>\OPDSDesk`.

В выбранном каталоге находятся `config.json`, `jobs.json`, `queue.db` и используемый по умолчанию каталог `Library\`.

## Совместимость с существующими данными

Это текущая техническая деталь выбора `APP_DATA_DIR`. Основным каталогом остаётся `<APP_DATA_BASE_DIR>\OPDSDesk`. Дополнительно код проверяет `<APP_DATA_BASE_DIR>\FlibustaBridge`.

Каталог считается содержащим состояние, если в нём есть хотя бы один из следующих объектов:

- `config.json`;
- `queue.db`;
- `jobs.json`;
- каталог `Library\`.

Алгоритм выбора следующий:

1. Если состояние найдено в `<APP_DATA_BASE_DIR>\OPDSDesk`, выбирается этот основной каталог.
2. Иначе, если состояние найдено в дополнительном каталоге, выбирается дополнительный каталог.
3. Если оба каталога не содержат перечисленных объектов, выбирается `<APP_DATA_BASE_DIR>\OPDSDesk`.

Код не копирует и не переносит файлы между этими каталогами автоматически.

## config.json

Файл `config.json` находится в активном `APP_DATA_DIR`. Он хранит конфигурацию приложения, выбранного OPDS-источника и каталога библиотеки. Текущая версия схемы — `config_version = 2`.

| Поле | Тип | Назначение и источник | Ручная настройка | Пример |
|---|---|---|---|---|
| `config_version` | целое число | Версия схемы; нормализуется приложением до текущего значения при необходимости | Обычно нет | `2` |
| `opds_url` | строка | Нормализованный URL успешно проверенного OPDS-источника | Через UI настроек OPDS | `https://catalog.example.org/opds` |
| `source_id` | строка | Внутренний идентификатор источника, вычисленный приложением | Нет | `sha256:<generated-value>` |
| `source_name` | строка | Название, полученное из корневой Atom-ленты при проверке источника | Нет | `Example Catalog` |
| `library_path` | строка | Абсолютный путь выбранной локальной библиотеки | Выбором каталога через UI | `C:\Books\OPDS` |
| `setup_complete` | логическое значение | Признак завершения первоначальной настройки | Устанавливается приложением | `true` |

### Чтение, нормализация и запись

При отсутствии `config.json` приложение начинает с пути библиотеки по умолчанию и с `setup_complete = false`, затем дополняет конфигурацию обязательными полями. Если файл существует, но его нельзя прочитать как подходящий JSON-объект, приложение продолжает работу с исходными значениями и нормализует их.

Нормализация устанавливает отсутствующие поля `opds_url`, `source_id`, `source_name`, `library_path` и `setup_complete`. Если `config_version` не является целым числом или меньше текущей версии схемы, устанавливается `2`. Неизвестные поля JSON-объекта при нормализации сохраняются.

Перед записью конфигурация нормализуется. Она записывается в `config.json.tmp`, после чего `os.replace()` заменяет итоговый `config.json`. Ошибки записи не скрываются этой функцией: вызывающий код получает ошибку и может показать её в интерфейсе. Этот механизм не является гарантией защиты от любых видов повреждения данных.

## Настройка OPDS-источника

OPDS-источник задаётся пользователем вручную; источника по умолчанию нет. Одновременно может быть настроен один источник.

Перед сохранением URL проходит проверку:

- принимаются только абсолютные HTTP и HTTPS URL с hostname;
- учётные данные внутри URL запрещены;
- URL нормализуется;
- приложение загружает корневую Atom-ленту и разбирает её;
- сохраняется нормализованный итоговый URL после redirect, если он был;
- `source_id` вычисляется приложением;
- `source_name` берётся из названия ленты.

Через UI текущий источник можно очистить. При этом очищаются только `opds_url`, `source_id` и `source_name`; остальные поля конфигурации сохраняются.

### source_id

`source_id` — внутренний стабильный идентификатор настроенного источника. Он строится из нормализованного URL как SHA-256 digest и имеет вид:

```text
sha256:<digest>
```

Пользователь обычно не задаёт `source_id` вручную.

## Каталог библиотеки

`library_path` хранит абсолютный путь к каталогу, в который приложение записывает загруженные книги.

Путь выбирается через системный folder picker pywebview. Выбранный каталог должен уже существовать. Перед сохранением приложение создаёт в нём временный файл проверки записи `.opds-desk-write-test-<uuid>.tmp` и удаляет его в блоке очистки. Если проверка записи не проходит, путь не сохраняется.

Значение по умолчанию вычисляется как:

```text
<APP_DATA_DIR>\Library
```

Это начальное значение, а не обязательное место хранения. Пользователь может выбрать другой каталог; в таком случае книги сохраняются в выбранный `library_path`.

## Переменные окружения

### LOCALAPPDATA

`LOCALAPPDATA` используется при вычислении базового каталога данных приложения. Если переменная отсутствует, код использует `os.path.expanduser("~")`, а затем добавляет `OPDSDesk` для основного каталога данных.

### OPDS_DESK_SECRET

Если `OPDS_DESK_SECRET` присутствует в окружении, его значение используется как Flask secret key для локального backend и поведения session cookie. Значение не следует публиковать в документах, логах или снимках экрана.

Код проверяет именно наличие переменной: пустая строка, если переменная задана, также будет использована как её значение. Для предсказуемого поведения задавайте непустое приватное значение.

### Совместимость с существующими настройками

Если `OPDS_DESK_SECRET` отсутствует, текущая реализация использует дополнительный compatibility fallback для secret key. Это деталь реализации; для явной конфигурации следует использовать `OPDS_DESK_SECRET`.

## Состояние очереди

`queue.db` — локальная база SQLite в активном каталоге данных. В ней логически хранятся:

- элементы очереди, их состояние, приоритеты, ошибки и снимки данных книг;
- настройки очереди, включая настройки планировщика;
- уведомления;
- записи о запусках очереди и их состоянии.

Для SQLite включается `PRAGMA journal_mode=WAL`. Во время работы рядом с `queue.db` могут присутствовать файлы `queue.db-wal` и `queue.db-shm`.

## Состояние заданий

`jobs.json` хранит сохранённое состояние массовых заданий: их статус, ход обработки, ошибки, выбранные книги и данные для возврата к исходному экрану. Схема файла динамическая и не фиксируется этим документом.

При запуске приложение читает `jobs.json`, если он существует. Задания со статусом ожидания или выполнения помечаются как прерванные. При изменении задания приложение сохраняет снимок состояния в `jobs.json.tmp`, затем заменяет итоговый файл через `os.replace()`. Если запись не удалась, код пытается удалить временный файл.

## Данные интерфейса

Помимо файлов в `APP_DATA_DIR`, интерфейс использует отдельный слой данных браузера и pywebview:

- Flask session cookie хранит данные текущего сеанса, включая URL контекста и возврата, используемые для навигации интерфейса;
- `sessionStorage` сохраняет выбор книг между страницами результатов OPDS-поиска в пределах текущего сеанса;
- `localStorage` хранит последний обработанный идентификатор уведомления в ключе `opdsDeskLastNotificationId`;
- pywebview запускается с `private_mode=False`, поэтому browser storage не переводится в private mode.

Эти данные не заменяют `config.json`, `queue.db` или `jobs.json`; это отдельный слой состояния интерфейса.

## Временные файлы загрузок

Во время загрузки используются файлы с суффиксом `.part`. Для acquisition-загрузок также используется временный артефакт с суффиксом `.opds-download.part`. Незавершённый файл не размещается сразу как итоговая книга: после успешной проверки файл переносится в конечный путь через `os.replace()`.

При запуске приложение обходит текущий каталог назначения `DESTINATION` и удаляет файлы, чьи имена заканчиваются на `.part`. Очистка выполняется до запуска планировщика очереди. Поэтому не следует хранить собственные важные файлы с таким суффиксом внутри каталога библиотеки.

## Резервное копирование

Для сохранения состояния приложения обычно важны:

- `config.json`;
- `jobs.json`;
- `queue.db`;
- выбранный каталог библиотеки, если нужно сохранить сами книги.

SQLite использует runtime-файлы WAL/SHM, поэтому простое копирование `queue.db` во время активной работы приложения может не соответствовать согласованному состоянию. Перед ручным резервным копированием закройте OPDS Desk. Если библиотека была выбрана вне `APP_DATA_DIR`, резервируйте её отдельно.

## Сброс конфигурации и состояния

### Сброс OPDS-источника

Предпочтительный способ — очистить текущий OPDS-источник через UI настроек. Это не требует ручного редактирования `config.json` и сохраняет остальные параметры конфигурации.

### Полный сброс локального состояния

Перед ручным удалением или изменением файлов закройте приложение и создайте резервную копию нужных данных. Каталог данных содержит разные типы состояния: удаление `config.json` само по себе не удаляет очередь, историю запусков или `jobs.json`. Удаление всего `APP_DATA_DIR` затрагивает значительно больше данных.

Библиотека может находиться как внутри `APP_DATA_DIR`, так и в отдельном выбранном пользователем каталоге. Не используйте автоматические destructive-команды удаления без предварительной проверки нужных данных и пути назначения.

## Данные, которые не следует публиковать

Не публикуйте без проверки следующие локальные данные:

- `config.json`;
- `jobs.json`;
- `queue.db`, `queue.db-wal`, `queue.db-shm`;
- `.env` и иные environment-файлы;
- закрытые ключи и сертификаты;
- снимки экрана с OPDS URL, локальными путями или идентификаторами;
- пользовательскую библиотеку.

Эти объекты не обязательно содержат пароли, но могут включать локальные пути, сведения об источниках, историю работы, идентификаторы или другие приватные данные.

## Пример config.json

Пример использует только условные значения и предназначен для объяснения структуры файла:

```json
{
  "config_version": 2,
  "opds_url": "https://catalog.example.org/opds",
  "source_id": "sha256:<generated-value>",
  "source_name": "Example Catalog",
  "library_path": "C:\\Books\\OPDS",
  "setup_complete": true
}
```

`source_id` обычно создаётся приложением после успешной проверки источника. Ручное редактирование `config.json` не является основным способом настройки OPDS Desk: для настройки источника и каталога библиотеки используйте UI.
