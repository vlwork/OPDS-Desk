# Выпуск релиза OPDS Desk

Этот документ описывает текущую ручную процедуру подготовки Windows-сборки OPDS Desk. Перед началом полезно свериться с документами [Разработка OPDS Desk](DEVELOPMENT.md), [Архитектура OPDS Desk](ARCHITECTURE.md) и [Конфигурация OPDS Desk](CONFIGURATION.md).

## Что считается релизом

Версия приложения задаётся константой `APP_VERSION` в `app.py`. Windows metadata хранится в `version_info.txt`, который подключён обоими PyInstaller spec-файлами.

Основной рекомендуемый артефакт сборки — onefile EXE. Onedir-сборка может выпускаться дополнительно, если она нужна для локальной проверки или выбранного способа распространения. Каталог `dist/` содержит локальные результаты сборки, игнорируется Git и не должен храниться как часть исходного кода репозитория.

Сборка выполняется вручную через PyInstaller. Эта процедура не предполагает автоматическую загрузку исполняемого файла на внешний сервис.

## Проверка состояния репозитория

Перед подготовкой релиза проверьте рабочее дерево:

```powershell
git status --short
```

Ожидается пустой вывод. Затем проверьте ошибки пробельных символов в unstaged changes:

```powershell
git diff --check
```

Если в рабочем дереве есть staged changes, дополнительно выполните:

```powershell
git diff --cached --check
```

Release-процедура не выполняет commit автоматически. Любые неожиданные изменения следует проверить до запуска сборки.

## Проверка версии

Текущая версия — 1.0.0. Её источники:

- runtime version: `APP_VERSION` в `app.py`;
- Windows metadata: `version_info.txt`;
- `FileVersion` и fixed file version;
- `ProductVersion` и fixed product version;
- `OPDS-Desk.spec` и `OPDS-Desk-OneFile.spec`, использующие `version_info.txt`.

Для текущей версии значения должны быть согласованы так:

```text
Runtime       : 1.0.0
ProductVersion: 1.0.0
FileVersion   : 1.0.0.0
```

Перед новым релизом обновите и проверьте все соответствующие runtime и Windows version fields. Несогласованные значения необходимо исправить до сборки окончательного артефакта сборки.

## Проверка Python-кода

Проверьте синтаксис `app.py`:

```powershell
.\.venv\Scripts\python.exe -m py_compile .\app.py
```

Ожидается завершение без ошибок и без диагностических сообщений об ошибках.

## Тестирование

Запустите полный unittest suite:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Релиз не следует собирать, если полный suite завершается с ошибкой. Фиксированное количество тестов не является требованием процедуры релиза: важно успешное завершение всех тестов, обнаруженных в текущем состоянии репозитория.

## Подготовка PyInstaller

PyInstaller не входит в `requirements.txt` и устанавливается отдельно в окружение разработки:

```powershell
.\.venv\Scripts\python.exe -m pip install PyInstaller
```

Версия PyInstaller не закреплена в репозитории, поскольку отдельного файла зависимостей для сборки нет. Перед сборкой убедитесь, что команда установки завершилась успешно.

## Очистка предыдущих build artifacts

Ручное удаление `build/` и `dist/` не является обязательным шагом этой процедуры. Обе команды сборки используют параметры `--clean` и `--noconfirm`: PyInstaller очищает свой build cache и не запрашивает интерактивное подтверждение замены результатов сборки.

Не используйте широкие destructive wildcard-команды для очистки рабочего каталога. После сборки проверяйте exit status PyInstaller и конкретный ожидаемый артефакт сборки.

## Onefile-сборка

Основная команда релизной сборки:

```powershell
.\.venv\Scripts\python.exe -m PyInstaller --clean --noconfirm .\OPDS-Desk-OneFile.spec
```

Ожидаемый артефакт сборки:

```text
dist\OPDS-Desk.exe
```

Убедитесь, что PyInstaller завершился успешно. Само наличие EXE недостаточно, если процесс сборки был прерван или завершился с ошибкой.

## Onedir-сборка

Onedir-сборка является дополнительной и не обязательна для каждого релиза:

```powershell
.\.venv\Scripts\python.exe -m PyInstaller --clean --noconfirm .\OPDS-Desk.spec
```

Ожидаемый артефакт сборки:

```text
dist\OPDS-Desk\OPDS-Desk.exe
```

Как и для onefile, проверяйте успешное завершение PyInstaller, а не только наличие выходного файла.

## Ручная проверка собранного приложения

Запустите onefile EXE:

```powershell
.\dist\OPDS-Desk.exe
```

Минимальный smoke test:

1. Приложение запускается без немедленной ошибки.
2. Desktop-окно имеет корректное название и версию.
3. Главный экран открывается.
4. First-run/setup работает на чистом состоянии.
5. Можно выбрать каталог локальной библиотеки.
6. OPDS-источник можно настроить вручную.
7. Поиск открывается, если источник предоставляет поддерживаемый search endpoint.
8. Каталог источника открывается.
9. Экран очереди доступен.
10. Тестовая книга поддерживаемого формата добавляется в очередь и загружается, если доступен безопасный тестовый OPDS-источник.

Если тестовый источник недоступен, проверку фактической загрузки не следует имитировать случайным публичным или приватным URL. Зафиксируйте её как отдельную незавершённую ручную проверку релиза.

## Проверка новой установки

В новом или чистом профиле Windows OPDS Desk не должен иметь заранее настроенный OPDS-источник. Основной fresh app-data root:

```text
%LOCALAPPDATA%\OPDSDesk
```

Проверку чистой установки следует выполнять в отдельном профиле Windows, VM, на тестовой машине или другом чистом ПК. Не удаляйте реальные application data пользователя без предварительной резервной копии. Проверка должна подтвердить открытие first-run/setup и возможность задать новый каталог библиотеки и OPDS-источник.

## Проверка Windows metadata

Получите metadata окончательного onefile EXE:

```powershell
(Get-Item .\dist\OPDS-Desk.exe).VersionInfo | Format-List FileDescription,ProductName,InternalName,OriginalFilename,FileVersion,ProductVersion
```

Для версии 1.0.0 ожидается:

```text
FileDescription  : OPDS Desk
ProductName      : OPDS Desk
InternalName     : OPDS-Desk
OriginalFilename : OPDS-Desk.exe
FileVersion      : 1.0.0.0
ProductVersion   : 1.0.0
```

Несоответствие metadata должно быть исправлено до публикации исполняемого файла. После исправления выполните новую сборку и повторите все проверки окончательного EXE.

## Контрольная сумма

После окончательной сборки вычислите SHA-256:

```powershell
Get-FileHash -Algorithm SHA256 .\dist\OPDS-Desk.exe
```

Если EXE пересобран, прежняя контрольная сумма больше не относится к окончательному исполняемому файлу и должна быть вычислена заново. Сохраните полученную контрольную сумму SHA-256 рядом с release notes или metadata публикуемого исполняемого файла. Сам документ не фиксирует контрольную сумму SHA-256 конкретной сборки.

## Версионированная копия

Для версии `X.Y.Z` создайте копию окончательного onefile EXE:

```powershell
Copy-Item .\dist\OPDS-Desk.exe .\dist\OPDS-Desk-X.Y.Z.exe
```

Для текущей версии команда выглядит так:

```powershell
Copy-Item .\dist\OPDS-Desk.exe .\dist\OPDS-Desk-1.0.0.exe
```

Проверьте равенство SHA-256 исходного и версионированного файлов:

```powershell
Get-FileHash -Algorithm SHA256 .\dist\OPDS-Desk.exe, .\dist\OPDS-Desk-1.0.0.exe
```

Обе строки должны содержать одинаковую контрольную сумму SHA-256.

## Финальная проверка репозитория

После сборки снова выполните:

```powershell
git status --short
```

Build artifacts из `build/` и `dist/` должны оставаться ignored и не появляться как tracked или untracked source changes. Если появились неожиданные изменения исходных файлов, релиз не следует считать завершённым до их проверки.

## Checklist релиза

1. Подтверждён clean `git status --short`.
2. Проверена согласованность runtime и Windows versions.
3. Успешно выполнен `py_compile`.
4. Успешно завершён полный unittest suite.
5. Успешно выполнена onefile-сборка.
6. При необходимости выполнена onedir-сборка.
7. Onefile EXE запускается.
8. Выполнен минимальный smoke test.
9. Проверено поведение новой установки.
10. Проверена Windows metadata.
11. Вычислен SHA-256 окончательной сборки.
12. Создана версионированная копия.
13. Подтверждено равенство контрольных сумм SHA-256 двух копий.
14. Выполнен финальный `git status --short`.

## Публикация

Фактическая процедура публикации в GitHub Releases пока не закреплена этим документом. Перед публикацией необходимо убедиться, что исполняемый файл, runtime version, Windows metadata и SHA-256 относятся к одной и той же окончательной сборке.
